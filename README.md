# amap-poi-aoi 使用说明

把一份含名称列的名单（CSV 或 Excel）批量查成高德 POI 候选，筛选后取 AOI 边界，导出 CSV 与两份 GeoJSON。

---

## 一、这个工具做什么

分两轮跑：

1. **第一轮出候选**：每个名称调一次高德搜索，命中的 POI 全部落库，并标注匹配度。
2. **第二轮取面**：在结果页按条件筛选、勾选，再对选中的记录逐个取 AOI 边界。

两轮分开是有原因的。实测搜「越秀公园」会返回 25 条结果，其中只有 1 条是公园本体，其余是园内的墓、亭、草坪和地铁口。先出点、再筛、再取面，能避免把调用额度浪费在无关条目上。

## 二、两种使用方式

### 方式 A：免安装版（不需要 Python）

1. 解压 `amap-poi-aoi-0.1.0-win64.zip` 到任意目录（路径别太深，不要放系统盘根目录）
2. 双击 `amap-poi-aoi.exe`
3. 等几秒，浏览器会自动打开 http://127.0.0.1:8000
4. 关闭那个黑色控制台窗口即停止服务

配置和数据库都落在 exe 同级的 `data` 目录里，想清空重来直接删这个目录。

### 方式 B：源码版（需要 uv 与 Node）

```bash
uv sync
cd frontend && npm ci && npm run build && cd ..
uv run uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

或者直接双击项目根目录的 `start.bat`。

浏览器打开 http://127.0.0.1:8000

## 三、输入文件要求（重要）

### 3.1 支持的格式

| 格式 | 说明 |
|---|---|
| `.csv` | UTF-8（带不带 BOM 都行）或 GBK |
| `.xlsx` | 只读第一张工作表 |
| `.xlsm` | 同 xlsx |

### 3.2 必须有表头行

第一行必须是列名。没有表头会直接报错（400），只填了表头没有数据行也会报错（422）。

### 3.3 名称列怎么被识别

工具按两步找名称列：

1. **先看表头**：列名里出现下列词就自动选中——
   `名称`、`name`、`公园名称`、`公园`、`地名`、`查询名称`、`关键词`、`标题`、`项目名称`
2. **再按内容推断**：如果表头都不匹配，就选「非数字占比高、平均长度 2—30 字」的那一列

两种方式都可能不准。**不准没关系**：上传后界面会显示前 10 行预览，下拉框里可以手动改名称列，改完再点创建任务。

### 3.4 行政区列（可选，建议加）

列名里出现 `行政区`、`区县`、`所在区`、`adname`、`地区`、`行政区划` 就会被自动识别。它只用于结果表的筛选和导出标注，不参与高德搜索。建议保留，否则上万条结果很难按区分批核对。

### 3.5 内容规则

| 规则 | 原因 |
|---|---|
| 一行一个名称 | 一个单元格塞多个名称（哪怕用逗号分隔）不会拆开查 |
| 单个名称不超过 80 字符 | 高德 keywords 上限就是 80；超长的会被直接标记 `name_too_long`，不消耗调用 |
| 空行会被跳过 | 导入结果里会显示跳过条数，不会报错 |
| 允许重复名称 | 重复的会各查一次；想省额度就在 Excel 里先去重 |
| 不要用合并单元格 | xlsx 的合并单元格只能读到左上角的值 |
| 名称写到「园区一级」 | 写「越秀公园」而不是「越秀公园北门」；后者会当成另一个地点去搜 |

### 3.6 最小示例

```csv
名称,行政区
越秀公园,越秀区
天河公园,天河区
流花湖公园,越秀区
```

Excel 里就是三列都不用，两列即可，第一行写列名。

### 3.7 一个实际问题：规划口径的长名搜不到

如果你用的是规划文件里的正式全名，例如「广州从化云台山区级森林自然公园」，高德通常搜不到——它只会返回云台花园、广州文化公园这类无关结果，匹配度会被标成 `weak`。

处理办法有两个：把名单换成常用名，或者跑完之后在结果页只看 `exact`（默认就是），把 `weak` 的记录单独人工处理。

## 四、配置项说明

首次使用先去「配置」页填高德 Web 服务 Key，然后点「测试接口」，会看到三段结果：Key 是否有效、地理编码是否正常、AOI 是否有权限。

| 设置 | 默认 | 说明 |
|---|---|---|
| 高德 API Key | 空 | 可以有多个，用「添加 Key」；请求会在它们之间轮换 |
| QPS 上限 | 3 | 每秒最多几次请求。填 0 表示不限速，不建议 |
| 单 Key 日上限 | 4500 | 单个 Key 当天用到这个数就换下一个 Key |
| 默认城市 adcode | 440100 | 广州。搜索范围限定在这个城市内 |
| 每 N 次请求休息 | 20 | 每完成 N 次请求随机休息一次，避免被风控 |
| 休息区间（秒） | 3—8 | 随机休息的取值范围 |
| 每个名称最多取多少条 POI | 25 条 × 1 页 | 对应高德的 `page_size` 与 `page_num`，最多 8 页 |
| 分类码前缀过滤 | 11 | 只保留风景名胜类（公园广场、景区）。留空会把地铁站、停车场一起收进来 |

## 五、操作流程

1. **配置页**：填 Key，点「测试接口」确认三段结果
2. **上传页**：拖入 CSV 或 Excel → 确认名称列（与行政区列）→ 点「创建任务」
3. **结果页**：点「开始采集」跑第一轮，进度条会显示已完成／失败条数
4. 第一轮回跑完，用「匹配度／行政区／关键词／AOI 状态」四项筛选；默认只看名称完全一致的候选，清空匹配度筛选可看全部
5. 勾选要取面的记录，或点「全选筛选结果」，再点「对选中项取 AOI」
6. 点「导出」选 CSV、GeoJSON(WGS-84) 或 GeoJSON(GCJ-02)

任务中途可以「暂停」和「继续」。配额用尽时任务会自动暂停，次日点「继续」就从没跑完的地方接着跑，已完成的记录不会重复请求。

## 六、输出格式

CSV 的列顺序固定：

```
query_name, match_level, poi_name, poi_id, poi_type, typecode,
address, adname, lng_gcj02, lat_gcj02, lng_wgs84, lat_wgs84,
aoi_status, aoi_area_ha
```

字段含义：

| 字段 | 说明 |
|---|---|
| `query_name` | 你名单里的原始名称 |
| `match_level` | `exact` 完全一致 / `contains` 包含关系 / `weak` 仅关键词命中 |
| `poi_name` | 高德返回的名称 |
| `poi_id` | 高德 POI 编号，取 AOI 用的就是它 |
| `typecode` | 高德分类码，`110101` 是公园 |
| `adname` | 所属行政区 |
| `lng_gcj02 / lat_gcj02` | 高德原生坐标 |
| `lng_wgs84 / lat_wgs84` | 转换后的坐标，导 GIS 用这套 |
| `aoi_status` | `ok` 取到面 / `no_aoi` 该 POI 没有面 / `error` 失败 / `pending` 未取 |
| `aoi_area_ha` | AOI 实测面积（公顷） |

GeoJSON 只包含 `aoi_status = ok` 的记录，`geometry` 是 Polygon，属性与 CSV 列一致。两种坐标系各导一份：

- WGS-84：叠卫星影像、和其它 GIS 数据一起用
- GCJ-02：在高德底图上对齐

## 七、常见问题

**AOI 全部失败，提示 10012**
这个 Key 没有 AOI 边界查询权限。它在高德属于高阶服务，需要在控制台提工单开通：https://console.amap.com/dev/ticket/create/66 。开通后在配置页重新点「测试接口」确认。

**任务暂停，提示日配额耗尽**
高德按账号计日调用量。次日点「继续」即可续跑。一把 Key 默认 4500 次/天，所以 1 万个名称大约要跑三天。

**候选太多看不过来**
第一轮默认按分类码前缀 `11` 过滤、每个名称最多取一页；结果表默认只显示名称完全一致的候选。想放宽就在配置页和筛选区调整。

**跑了很久没动静**
QPS 默认 3，加上每 20 次休息 3—8 秒，1 万个名称大约需要 1.5 小时纯等待时间；看进度条或耐心等，别重复点「开始采集」。

**想换一份名单重跑**
重新上传一份即可，会建一个新任务，旧任务的数据留着，互不影响。
