# 决策记录

按时间倒序记录影响实现的决定、当时的理由，以及被否决的选项。

## D-019 产物不入版本库

- 时间：2026-09-24
- 决定：`.gitignore` 增加 `dist/` 与 `build/`；exe 与两个 zip 只作为 GitHub Release 附件发布。
- 理由：22.8 MB 的二进制放进仓库会永久留在 Git 历史里，clone 变慢且无法有效删除。

## D-018 同一仓库发两个版本

- 时间：2026-09-24
- 决定：不维护两个仓库，而是在同一个 Release 里挂两个附件——`*-source.zip`（git ls-files 导出，不含 exe）与 `*-win64.zip`（含 exe）。
- 理由：源码永远只有一份，避免两套代码漂移；使用者按自己有没有 Python 环境挑一个下载即可。

## D-017 数据目录放在 exe 同级

- 时间：2026-09-24
- 决定：冻结运行时把 `DATA_DIR` 设为 exe 同级的 `data/`，而不是系统用户目录。
- 理由：绿色软件的使用习惯，想清空配置直接删这个目录；同时避免写到 `Program Files` 这类无权限位置。

## D-016 打包用 onedir 而不是 onefile

- 时间：2026-09-24
- 决定：PyInstaller 使用 `--onedir`。
- 理由：onefile 每次启动都要把内容解包到临时目录，启动慢，且更容易被杀毒软件误报；onedir 启动快、排错也方便（能直接看到 `_internal` 里的依赖）。

## D-015 结果表默认只看完全一致

- 时间：2026-09-24
- 决定：结果表的「匹配度」筛选默认勾选 `exact`，清空后可查看全部候选。
- 理由：实测越秀公园 25 条候选里只有 1 条名称完全一致（公园本体），默认展示全部会直接面对几十条子点位。

## D-014 权限不足暂停任务而不是逐条报错

- 时间：2026-09-24
- 决定：AOI 返回 10012 时把任务置为 paused，reason 写明「需提工单开通」；不逐条把记录标成失败。
- 理由：Key 一旦没有权限，后续每条都会失败，逐条报错既浪费调用又没有信息量；暂停能先解决权限问题。

## D-013 候选过滤：分类码前缀与分页上限

- 时间：2026-09-24
- 决定：新增三个设置项——`poi_page_size`（默认 25）、`poi_max_pages`（默认 1）、`typecode_prefix`（默认 `11`），并在第二轮用它们过滤候选。
- 理由：真实冒烟显示，搜「越秀公园」会返回「越秀公园-伍廷芳墓」「越秀公园地铁站A口」「越秀公园篮球场」等 25 条，绝大多数是公园内部点位或交通设施；按分类码前缀 `11`（风景名胜类）过滤后剩 15 条，再按名称完全一致收敛到 1 条。
- 取舍：过滤条件都可关掉（前缀留空），但默认打开以避免上万条名称时产生几十万条记录。

## D-012 前端启用 legacy-peer-deps

- 时间：2026-09-23
- 决定：`frontend/.npmrc` 写入 `legacy-peer-deps=true`。
- 理由：模板自带 TypeScript 6.0.2，而 openapi-typescript 的 peer 范围只到 5.x，普通 `npm install` 直接报 ERESOLVE。
- 影响：clone 后 `npm ci` 可正常安装；如未来 TS 降到 5.x 可移除该文件。

## D-011 列识别与任务接口前移到 Phase 2

- 时间：2026-09-23
- 决定：把「读取 CSV／XLSX 并识别名称列」放在后端 `app/services/ingest.py`，并在 Phase 2 就实现 `/api/tasks/preview`、`/api/tasks`、`/api/tasks/{id}`、`/api/records`。
- 理由：测试名单是 Excel 格式，前端解析 xlsx 需要额外库；放后端可让 CSV 与 xlsx 共用一套规则，且预览与建任务用同一实现，避免口径分叉。同时让 Phase 2 的每个页面都有真实接口可测，符合「每阶段都要测前后端接口」的要求。
- 边界：两轮采集管道（真正的 PoI／AOI 请求）仍在 Phase 3。

## D-010 契约方式：OpenAPI 生成前端类型

- 时间：2026-09-23
- 决定：后端导出 `openapi.json`，前端用 `openapi-typescript` 生成类型并纳入类型检查。
- 理由：接口有七个且两轮管道会反复调字段，让字段漂移在类型检查阶段暴露比在联调阶段发现更省事。
- 否决：前端手写类型加响应快照对比（改名要动两处，且只覆盖写了快照的响应）。

## D-009 字段准绳：以后端真实返回为准

- 时间：2026-09-23
- 决定：新增字段核对脚本（计划中的 Task 3.8），采集后端运行时真实返回的字段，与 openapi 声明和前端字段做差集；通过后才允许进入 Phase 4。
- 理由：类型生成抓不到「运行时返回了但响应模型没声明」的字段，需要运行时采集补齐。

## D-008 每阶段都要测第三方接口

- 时间：2026-09-23
- 决定：每个阶段的完成标志都包含前后端接口测试与第三方接口测试；真实调用每阶段限定 5—10 次并全部记账。
- 理由：高德接口有限流与配额，且实测发现规划口径的公园全名匹配率低，早测早暴露。

## D-007 高德 MCP Server 用于交叉验证

- 时间：2026-09-23
- 决定：把 `@amap/amap-maps-mcp-server` 配到本机，用它的关键词搜索与地理编码对自建客户端做交叉验证。
- 边界：MCP 的 16 项能力不含 AOI 边界查询，AOI 只能走 HTTP 接口。

## D-006 请求节奏

- 时间：2026-09-23
- 决定：不做逐次 sleep；每完成 20 次请求后随机休息 3—8 秒，阈值与区间在界面可配；全局 QPS 上限默认 3。
- 理由：需求是「不要每次请求都休息，攒到一定次数再随机休息」，同时要避免触发风控。

## D-005 名称清洗策略

- 时间：2026-09-23
- 决定：只做前缀清洗（去掉广东省／广东／广州市／广州），不做后缀变体替换；匹配分 exact／contains／weak 三档，weak 与非 11xxxx 分类码的候选默认标记为疑似不相关。
- 理由：实测规划全名「广州从化云台山区级森林自然公园」在高德搜不到目标，返回的是云台花园、广州文化公园、广州雕塑公园；清洗只能解决一部分，剩下的交人工。

## D-004 AOI 走官方 V5 接口

- 时间：2026-09-23
- 决定：AOI 边界一律走 `v5/aoi/polyline`，不做浏览器自动化兜底。
- 依据：官方文档中 AOI 边界查询只有 V5 一个接口；行政区域查询的 keywords 只支持行政区名称／citycode／adcode，实测传公园名返回空数组。
- 前置：需提工单开通权限，实测当前 Key 返回 10012。

## D-003 两轮流程

- 时间：2026-09-23
- 决定：第一轮只出 POI 候选（全部保留），界面按匹配度／行政区／关键词批量筛选后，第二轮只对选中的 poi_id 取 AOI。
- 理由：上万条名称时逐条人工确认不现实，先出点位再批量筛选能显著减少 AOI 请求量。

## D-002 不要地图预览

- 时间：2026-09-23
- 决定：前端不做地图，只做配置、上传、进度、结果表格与导出；大规模数据的核对靠筛选项与搜索定位。

## D-001 技术栈

- 时间：2026-09-23
- 决定：后端 FastAPI + SQLModel/SQLite（uv 管理 Python 3.12），前端 Vue3 + Vite + Element Plus，本机运行，许可证 MIT。
- 否决：后端托管静态页（界面复杂后不好维护）；Docker 部署（当前只需本机运行）。
